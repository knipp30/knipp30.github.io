Node Maintenance and OpenShift Virtualization Updates

Configure node maintenance resources, prepare nodes for maintenance using CLI, drain nodes correctly.

Node Maintenance Overview

# node-maintenance-operator (NMO) is deployed standalone from OperatorHub
# Not shipped with OpenShift Virtualization anymore

# NodeMaintenance CR watches:
# - New CRs: Node is cordoned, no new workloads scheduled, evictable pods drained
# - Deleted CRs: Node made available for new workloads

# Node maintenance achieves same results as:
# oc adm cordon + oc adm drain

# IMPORTANT: VMs must have RWX storage to be live migrated
# Non-migratable VMs will be stopped during maintenance

Configuring Node Maintenance Resources

# Install Node Maintenance Operator
cat > nmo-subscription.yaml <<EOF
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: node-maintenance-operator
  namespace: openshift-workload-availability
spec:
  channel: stable
  name: node-maintenance-operator
  source: redhat-operators
  sourceNamespace: openshift-marketplace
EOF

oc apply -f nmo-subscription.yaml

# Create NodeMaintenance CR
cat > node-maintenance.yaml <<EOF
apiVersion: nodemaintenance.medik8s.io/v1beta1
kind: NodeMaintenance
metadata:
  name: worker-0-maintenance
spec:
  nodeName: worker-0
EOF

oc apply -f node-maintenance.yaml

# Verify node is cordoned
oc get nodes worker-0
# Expected: SchedulingDisabled

# Delete NodeMaintenance CR when done
oc delete nodemaintenance worker-0-maintenance

Preparing Nodes for Maintenance (CLI)

# Step 1: Cordon node (stop scheduling)
oc adm cordon <node_name>

# Step 2: Drain node (evict pods/VMs)
oc adm drain <node_name> --force=true \
  --ignore-daemonsets \
  --delete-emptydir-data \
  --timeout=5m \
  --skip-wait-for-delete-timeout=0

# Step 3: Verify node is ready for maintenance
oc get nodes <node_name>
# Should show: NotReady,SchedulingDisabled or Ready,SchedulingDisabled

# Step 4: When maintenance is complete
oc adm uncordon <node_name>

Draining Nodes Correctly

# Proper drain sequence for VMs with live migration
# 1. Cordon the node
oc adm cordon <node_name>

# 2. Drain with appropriate settings
oc adm drain <node_name> \
  --ignore-daemonsets \
  --force \
  --delete-emptydir-data

# 3. Monitor migration progress
oc get vmim -A

# 4. Verify VMs have migrated
oc get vmi -A

# For non-migratable VMs (RWO storage, GPUs):
# - Set evictionStrategy: LiveMigrateIfPossible
# - VM will be stopped, not migrated
# - Use evictionStrategy: None to power down

# For bare metal nodes:
# - More time needed for maintenance
# - Workloads need to restart elsewhere
# - Node maintenance mode gracefully powers down nodes
# - Detailed progress and status provided during maintenance

Managing Node Labeling for CPU Models

# Node labeller manages CPU model labels
# Obsolete CPU models are automatically filtered

# Default obsolete CPU models (cannot be removed):
# 486, Conroe, athlon, core2duo, coreduo, kvm32, kvm64, n270,
# pentium, pentium2, pentium3, pentiumpro, phenom, qemu32, qemu64

# Add to obsolete CPU list
cat > obsolete-cpus.yaml <<EOF
apiVersion: hco.kubevirt.io/v1beta1
kind: HyperConverged
metadata:
  name: kubevirt-hyperconverged
  namespace: openshift-cnv
spec:
  obsoleteCPUs:
    cpuModels:
    - "obsolete-cpu-model-1"
    - "obsolete-cpu-model-2"
EOF

oc apply -f obsolete-cpus.yaml

# Skip node from labelling
oc annotate node <node_name> node-labeller.kubevirt.io/skip-node=true

# Remove annotation to resume labelling
oc annotate node <node_name> node-labeller.kubevirt.io/skip-node-

Deleting Failed Nodes

# If a node fails without machine health checks:
# 1. Mark node unschedulable
oc adm cordon <node_name>

# 2. Drain all pods
oc adm drain <node_name> --force=true

# 3. Delete node
oc delete node <node_name>

# 4. Nodes with runStrategy: Always are rescheduled
# 5. Verify VM failover
oc get vmis -A

Kernel Samepage Merging (KSM)

# KSM deduplicates identical data in VM memory pages
# Activates when nodes are overloaded
# IMPORTANT: Only use KSM with trusted workloads

# Enable KSM for all nodes
cat > ksm-all.yaml <<EOF
apiVersion: hco.kubevirt.io/v1beta1
kind: HyperConverged
metadata:
  name: kubevirt-hyperconverged
  namespace: openshift-cnv
spec:
  configuration:
    ksmConfiguration:
      nodeLabelSelector: {}
EOF

# Enable KSM on subset of nodes
cat > ksm-selective.yaml <<EOF
apiVersion: hco.kubevirt.io/v1beta1
kind: HyperConverged
metadata:
  name: kubevirt-hyperconverged
  namespace: openshift-cnv
spec:
  configuration:
    ksmConfiguration:
      nodeLabelSelector:
        matchLabels:
          node-role.kubernetes.io/compute: "true"
EOF

# KSM node labels:
# kubevirt.io/ksm-handler-managed: "true" when KSM activated
# kubevirt.io/ksm-enabled: "true" when KSM enabled

# Disable KSM
oc edit hyperconverged kubevirt-hyperconverged -n openshift-cnv
# Remove the ksmConfiguration stanza

Updating OpenShift Virtualization

# Updating the HyperConverged operator updates all components
# Update via web console or CLI

# Via CLI:
oc edit subscription hco-operatorhub -n openshift-cnv
# Change to desired channel/CSV

# Or update HyperConverged CR
cat > update-hc.yaml <<EOF
apiVersion: hco.kubevirt.io/v1beta1
kind: HyperConverged
metadata:
  name: kubevirt-hyperconverged
  namespace: openshift-cnv
spec:
  uninstallStrategy: UninstallAvailable
  workloadUpdateStrategy:
    workloadsUpdateStrategy: Drain
EOF

# Monitoring update progress
oc get hco kubevirt-hyperconverged -n openshift-cnv -o jsonpath='{.status.conditions[*].status}'

Web Console Steps

# Via Web Console:
# 1. Navigate to Virtualization → VirtualMachines
# 2. Select a VM → Policies tab
# 3. Configure eviction strategy (LiveMigrate, LiveMigrateIfPossible, or None)
# 4. Click Save
# 5. For KSM configuration:
#    a. Navigate to Virtualization → Settings → Cluster
#    b. Scroll to "Kernel Samepage Merging" section
#    c. Enable KSM and configure nodeLabelSelector
#    d. Click Save
# 6. For Virtualization updates:
#    a. Navigate to OperatorHub → Installed Operators
#    b. Select "OpenShift Virtualization"
#    c. Go to Updates tab
#    d. Change update channel or approval strategy
#    e. Click OK to approve update
