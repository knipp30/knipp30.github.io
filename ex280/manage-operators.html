Manage OpenShift Operators

Install, uninstall, and delete OpenShift operators.

Overview

Operators extend Kubernetes with automated management capabilities. OpenShift Operators are packaged using the Operator Lifecycle Manager (OLM).

Installing an Operator

# Method 1: Using the web console
# 1. Navigate to Operators → OperatorHub
# 2. Browse or search for an operator
# 3. Click to install
# 4. Choose install namespace and approval strategy
# 5. Click Install

# Method 2: Using CLI
# 1. Create a Namespace for the operator
oc create namespace my-operator-ns

# 2. Create a CatalogSource (if not using default catalog)
cat > catalogsource.yaml <<'EOF'
apiVersion: operators.coreos.com/v1alpha1
kind: CatalogSource
metadata:
  name: my-catalog
  namespace: openshift-marketplace
spec:
  displayName: My Operator Catalog
  image: registry.redhat.io/redhat/redhat-operator-index:v4.18
  sourceType: grpc
EOF

oc apply -f catalogsource.yaml

# 3. Create a Subscription
cat > subscription.yaml <<'EOF'
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: my-operator
  namespace: my-operator-ns
spec:
  channel: stable
  name: my-operator
  source: my-catalog
  sourceNamespace: openshift-marketplace
  installPlanApproval: Automatic
EOF

oc apply -f subscription.yaml

# 4. Verify installation
oc get pods -n my-operator-ns
oc get csv -n my-operator-ns
oc get subscriptions -n my-operator-ns

# 5. Create the Operator instance (CRD)
cat > operator-instance.yaml <<'EOF'
apiVersion: example.com/v1
kind: MyOperator
metadata:
  name: my-operator-instance
  namespace: my-operator-ns
spec:
  # Operator-specific configuration
  replicas: 1
EOF

oc apply -f operator-instance.yaml

Uninstalling an Operator

# Step 1: Delete the Operator instance (CRD)
oc delete myoperator/my-operator-instance -n my-operator-ns

# Step 2: Delete the Subscription
oc delete subscription my-operator -n my-operator-ns

# Step 3: Delete the ClusterServiceVersion (CSV)
oc delete csv -n my-operator-ns my-operator.1.0.0

# Step 4: Delete the Operator deployment
oc delete deployment -n my-operator-ns my-operator

# Step 5: (Optional) Delete the CatalogSource if you created one
oc delete catalogsource my-catalog -n openshift-marketplace

# Step 6: (Optional) Delete the namespace
oc delete namespace my-operator-ns

# Verify cleanup
oc get pods -n my-operator-ns  # Should be empty
oc get csv -n my-operator-ns  # Should be empty

Deleting an Operator

# Complete deletion (same as uninstall but more thorough)
# 1. Delete all instances of the operator's CRD
oc delete -l app=my-operator --all -n my-operator-ns

# 2. Delete the subscription
oc delete subscription my-operator -n my-operator-ns

# 3. Delete the CSV
oc delete csv -n my-operator-ns $(oc get csv -n my-operator-ns -o jsonpath='{.items[*].metadata.name}')

# 4. Delete the operator deployment and related resources
oc delete deployment -n my-operator-ns -l app=my-operator
oc delete serviceaccount -n my-operator-ns -l app=my-operator
oc delete clusterrole -l app=my-operator
oc delete clusterrolebinding -l app=my-operator

# 5. Delete CatalogSource (if custom)
oc delete catalogsource -n openshift-marketplace my-catalog

# 6. Delete the namespace
oc delete namespace my-operator-ns

# Verify complete removal
oc get all -n my-operator-ns 2>/dev/null || echo "Namespace deleted"

Managing Operator Lifecycles

# View available channels for an operator
oc get subscription -n my-operator-ns -o yaml

# Upgrade an operator to a newer version
oc edit subscription my-operator -n my-operator-ns
# Update the spec.channel or spec.source

# View operator history
oc get csv -n my-operator-ns --sort-by=.metadata.creationTimestamp

# View operator conditions
oc describe csv <csv-name> -n my-operator-ns

# Check operator installation status
oc get subscriptions -n my-operator-ns
oc get csv -n my-operator-ns

# Change approval strategy
# Automatic: InstallPlan is auto-applied
# Manual: InstallPlan must be manually approved

# For manual approval:
oc get installplan -n my-operator-ns
oc patch installplan <installplan-name> -n my-operator-ns --type merge -p '{"spec":{"approved":true}}'

OLM Concepts

# Key OLM objects:
#   CatalogSource: Where operators are sourced from
#   Subscription: Watches for operator updates
#   ClusterServiceVersion (CSV): Defines the operator version
#   InstallPlan: The plan to install/upgrade an operator
#   OperatorGroup: Defines target namespaces for operators

# OperatorGroup configuration
cat > operatorgroup.yaml <<'EOF'
apiVersion: operators.coreos.com/v1alpha2
kind: OperatorGroup
metadata:
  name: my-operator-group
  namespace: my-operator-ns
spec:
  targetNamespaces:
  - my-operator-ns
  updateStrategy:
    registryPoll:
      interval: 10m
EOF

oc apply -f operatorgroup.yaml
