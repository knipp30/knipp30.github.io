Manage OpenShift Container Platform

Web console, CLI management, projects, images, resource queries, monitoring, logs, health assessment, and troubleshooting.

Overview

This section covers the core OpenShift administration tasks required for EX280. All configurations must persist after reboot.

Web Console Management

# Access the web console
# Navigate to https://<cluster-api>:6443

# Key console areas:
#   - Home → Overview of cluster status
#   - Administrator → Cluster Settings, Storage, Networking
#   - Developer → Projects, Applications, Topology
#   - OperatorHub → Install operators

CLI Management (oc)

# Login to the cluster
oc login https://<cluster-api>:6443 -u <user> -p <password>

# Or using a token
oc login https://<cluster-api>:6443 --token=<token>

# View cluster version
oc get clusterversion

# View cluster operators status
oc get co

# View operator status with additional detail
oc get co -o wide

# Check operator conditions
oc describe clusteroperators <operator>

# View node status
oc get nodes -o wide

Creating and Deleting Projects

# Create a project
oc new-project my-app

# Or using oc create
oc create project my-app --description="My Application" --annotations="purpose=testing"

# Switch to a project
oc project my-app

# List current project
oc project

# List all projects
oc get projects

# Delete a project
oc delete project my-app

# Create project with resource limits
oc create project my-project
oc annotate namespace my-project kubernetes.io/description="Production app"

Container Images

# List images in a project
oc get imagestreams -n <project>

# View image stream tags
oc get is <image-stream-name> -n <project>

# View image details with digests
oc describe imagestream <image-stream-name> -n &<project>

# Identify images by tags and digests
oc get is <image-stream-name> -o jsonpath='{.status.tags[].items[*].dockerImageReference}' -n <project>

# Import an image from an external registry
oc import-image <image-name>:<tag> --from=<registry>/<repo>/<image> -n <project>

# Create an ImageStream from a Docker image
oc create image-stream my-stream --docker-image=<registry>/<image>:<tag> -n <project>

Query, Format, and Filter Resources

# Basic get with various output formats
oc get pods -o wide
oc get pods -o yaml
oc get pods -o json
oc get pods -o jsonpath='{.items[*].metadata.name}'

# Filter by label selector
oc get pods -l app=myapp
oc get pods -l 'app in (myapp, otherapp)'
oc get pods -l 'app notin (blockedapp)'
oc get pods -n <project> -l env=prod

# Filter by field selector
oc get pods --field-selector=status.phase=Running
oc get pods --field-selector=status.phase=Failed

# Watch resources for changes
oc get pods -w
oc get pods --watch

# Get specific fields
oc get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.podIP}{"\n"}{end}'

# Describe resources for detailed info
oc describe pod <pod-name>
oc describe svc <svc-name>
oc describe route <route-name>

Import, Export, and Configure Resources

# Export resources to a file
oc get svc,deploy,pods -o yaml > resources.yaml
oc get <resource-type>/<resource-name> -o yaml > resource.yaml

# Apply from a file
oc apply -f resources.yaml

# Create from a file
oc create -f resources.yaml

# Replace existing resources
oc replace -f resources.yaml --force

# Dry run (test without applying)
oc apply -f resources.yaml --dry-run=client
oc apply -f resources.yaml --dry-run=server

# Edit resources directly
oc edit pod <pod-name>
oc edit deploy <deploy-name>

# Patch resources
oc patch deploy <deploy-name> -p '{"spec":{"replicas":3}}'
oc patch pod <pod-name> -p '{"spec":{"nodeSelector":{"disktype":"ssd"}}}'

Cluster Status and Health

# Overall cluster health
oc get co

# Check for degraded operators
oc get co | grep Degraded

# Get cluster events
oc get events --sort-by=.metadata.creationTimestamp

# Get events in a project sorted by severity
oc get events --sort-by=.lastTimestamp -n <project>

# Get events from the last hour
oc get events --since=1h

# Check node conditions
oc get nodes -o jsonpath='{range .items[*].status.conditions[*]}{.type}{"\t"}{.status}{"\n"}{end}'

# Check node resources
oc adm top nodes
oc adm top pods --sort-by=memory -n <project>

Monitoring and Alerts

# View Prometheus metrics (if accessible)
# Default Prometheus at: https://<cluster-api>:6443/api/v1/namespaces/openshift-monitoring/services/http-prometheus:8080/proxy

# Check Thanos Querier
oc get svc -n openshift-monitoring | grep thanos

# Get alerts
oc get prometheusrules -n <project>

# View alertmanager config
oc get secret alertmanager-main -n openshift-monitoring -o jsonpath='{.data.data\.yaml}' | base64 -d

# Check monitoring operator
oc get co kube-apiserver
oc get co openshift-monitoring

Viewing Logs

# View pod logs
oc logs <pod-name>

# View logs of a specific container in a multi-container pod
oc logs <pod-name> -c <container-name>

# Follow logs in real-time
oc logs -f <pod-name>

# View logs from previous instance of a pod
oc logs <pod-name> --previous

# View logs with timestamps
oc logs <pod-name> --timestamps

# Get logs from all pods matching a label
oc logs -l app=myapp

# Get logs from a specific namespace
oc logs <pod-name> -n <project>

# View logs from a deployment's pods
oc logs -f dc/<deploy-config-name>

# Get logs from a daemonset's pods
oc logs -f ds/<ds-name>

# View controller manager logs
oc logs -n openshift-kube-apiserver kube-apiserver-<node>

# View etcd logs (cluster admin)
oc logs -n openshift-etcd etcd-<node>

Health Assessment

# Comprehensive health check
oc adm diagnostics

# Check operator health
oc get co -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.conditions[-1:].type}{"\t"}{.status.conditions[-1:].status}{"\n"}{end}'

# Check etcd cluster health (cluster admin)
oc adm diagnostic etcd-check-cluster-connected

# Check API server health
oc adm diagnostic api-server-check-etcd-connected

# Node diagnostics
oc adm diagnostics node-config-reflector

# Storage diagnostics
oc adm diagnostics storage

# Network diagnostics
oc adm diagnostics network

# Check pod status comprehensively
oc get pods --all-namespaces | grep -v Running

# Check for pods in error state
oc get pods --all-namespaces | grep -E 'ERROR|CrashLoop|Pending'

# Check for failed nodes
oc get nodes | grep -v Ready

# Check for pending PVCs
oc get pvc --all-namespaces | grep Pending

Troubleshooting

# Pod troubleshooting steps
oc describe pod <pod-name> -n <project>

# Check pod events
oc get events --field-selector involvedObject.name=<pod-name> -n <project> --sort-by=.metadata.creationTimestamp

# Check container status details
oc get pod <pod-name> -o jsonpath='{.status.containerStatuses[*]}' -n <project>

# Common issues:
#   ImagePullBackOff: Check image name, registry credentials
#   CrashLoopBackOff: Check logs, resource limits
#   Pending: Check node resources, PVCs, tolerations
#   ErrImagePull: Verify image path and tags
#   ContainerCreating: Check volume mounts, security contexts

# Node troubleshooting
oc describe node <node-name>
oc get events --field-selector involvedObject.name=<node-name>

# Service troubleshooting
oc get svc <svc-name> -n <project>
oc get endpoints <svc-name> -n <project>
oc debug node/<node-name>

# Network troubleshooting
oc debug pod/<pod-name> -n <project>
# Inside debug session:
#   curl http://<service-name>:<port>
#   nc -zv <service-name> <port>

# DNS troubleshooting
nslookup kubernetes.default.svc.cluster.local
dig kubernetes.default.svc.cluster.local @<dns-ip>

Using Product Documentation

# Access documentation in-cluster
oc logs -n openshift-bookinfo deployment/documentation

# View CLI help
oc help
oc create --help
oc apply --help

# Get resource-specific help
oc explain pod
oc explain pod.spec
oc explain pod.spec.securityContext
oc explain service.spec.ports
oc explain route.spec
