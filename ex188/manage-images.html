Study Points for the Exam

1. Private Registry Security

Authenticate to registries before pushing or pulling images:

# Login to a registry
podman login registry.example.com
podman login quay.io
podman login registry.redhat.com -u <username> -p <password>

# Authentication file is stored at $XDG_RUNTIME_DIR/containers/auth.json
# or $HOME/.config/containers/auth.json

# Logout
podman logout registry.example.com

Red Hat registry: Requires a Red Hat account and pull secret. Access images from registry.redhat.io or registry.access.redhat.com.

2. Interacting with Different Registries

Podman works with multiple registry types:

  • Docker Hub: docker.io/library/alpine:latest
  • Quay.io: quay.io/myorg/myimage:tag
  • Red Hat Registry: registry.redhat.io/myapp/myimage:tag
  • Local registry: localhost/myimage:tag
  • Custom registry: registry.example.com:5000/myimage:tag

Image naming convention: [registry/]repository[:tag]

3. Image Tags

Tag images to identify specific versions or builds:

# Tag an image
podman tag myimage:latest myimage:v1.2.3
podman tag myimage:latest registry.example.com/myimage:v1

# List image tags
podman images
podman images --digests

Best practices:

  • Use meaningful tags: version numbers, build hashes, environment names
  • Always tag images before pushing to a registry
  • Use latest sparingly — it is implicit and can cause confusion
  • Consider using semantic versioning (e.g., v1.2.3)

4. Push and Pull Images

# Push an image to a registry
podman push myimage:latest registry.example.com/myimage:latest

# Pull an image from a registry
podman pull registry.example.com/myimage:latest

# Pull and run in one step
podman run registry.example.com/myapp:latest

Push authentication: Requires prior podman login. For Red Hat registries, use your developer.redhat.com credentials.

5. Backup: Image with Layers vs. Container State

Back up an image (includes all layers and metadata):

# Save image with all layers and metadata to a tar file
podman save -o myimage.tar myimage:latest

# Load from a tar file
podman load -i myimage.tar

Back up a container state (changes made since creation):

# Commit container changes to a new image
podman commit <container_id> myimage:from-container

# Export container filesystem (does not include layers or metadata)
podman export <container_id> -o container-export.tar
cat container-export.tar | podman import - myimage:imported

Key differences:

  • podman save preserves the full image with all layers, metadata, and history
  • podman commit captures the current state of a running container as a new image
  • podman export only saves the container filesystem — loses layers, metadata, and history
  • podman import restores from an exported tarball as a single-layer image
