Study Points for the Exam

1. Understand the Description of Application Resources

List containers and their status:

# List running containers
podman ps

# List all containers (including stopped/exited)
podman ps -a

# Filter by name, status, or label
podman ps --filter name=myapp
podman ps --filter status=exited

Inspect container resources:

# Full container inspection (JSON output)
podman inspect myapp

# Inspect specific fields
podman inspect --format '{{.State.Status}}' myapp
podman inspect --format '{{.NetworkSettings.IPAddress}}' myapp
podman inspect --format '{{.Mounts}}' myapp

# Inspect image configuration
podman inspect myimage

Common State values: created, running, paused, restarting, exited, dead

2. Get Application Logs

# View all logs
podman logs myapp

# Follow logs in real time
podman logs -f myapp

# Show last N lines
podman logs --tail 100 myapp

# Filter by time range
podman logs --since 30m myapp
podman logs --since "2026-01-01T00:00:00" myapp

# Show only errors
podman logs 2>&1 | grep -i error

Log troubleshooting:

  • Check if the container is actually running: podman ps
  • Check exit codes: podman inspect --format '{{.State.ExitCode}}' myapp
  • Check container health (if health check is configured)

3. Inspect Running Applications

# View process information inside a container
podman top myapp

# View container stats (CPU, memory, network I/O)
podman stats myapp

# Check container ports
podman port myapp

# View container network configuration
podman network inspect myapp

# Check mounted volumes
podman inspect --format '{{json .Mounts}}' myapp

4. Connecting to Running Containers

# Attach to a running container with an interactive shell
podman exec -it myapp sh

# Execute a specific command
podman exec myapp ls -la /app

# Run as a different user
podman exec -u root -it myapp bash

# Detached exec (run a command in background)
podman exec -d myapp touch /tmp/trigger

Use cases for podman exec:

  • Debug application issues by examining files
  • Check environment variables: podman exec myapp env
  • Test connectivity: podman exec myapp ping google.com
  • View application logs inside the container: podman exec myapp cat /var/log/app.log
  • Restart services: podman exec myapp systemctl restart nginx

5. Common Troubleshooting Scenarios

Container won't start

# Check logs for error messages
podman logs myapp

# Check if the image exists
podman images

# Try running interactively for verbose output
podman run -it --rm myimage bash

Container exits immediately

# Check exit code
podman inspect --format '{{.State.ExitCode}}' myapp

# Check logs
podman logs myapp

# Run with an interactive shell to debug
podman run -it --rm myimage /bin/sh

Port not accessible

# Check if port is mapped
podman port myapp

# Check if service is listening inside container
podman exec myapp ss -tlnp

# Check container network
podman inspect --format '{{json .NetworkSettings}}' myapp

Permission issues

# Check container user
podman exec myapp whoami

# Check file permissions
podman exec myapp ls -la /path/to/file

# Check SELinux context on bind mounts
ls -Z /host/path
