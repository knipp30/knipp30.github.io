Model Monitoring

Monitor bias and drift with TrustyAI, track hardware with Prometheus/Grafana

Model Monitoring Overview

RHOAI provides multiple monitoring capabilities:

  • TrustyAI — Bias detection, data drift, concept drift monitoring
  • OpenShift Monitoring Stack — Prometheus + Grafana for hardware metrics
  • KServe Metrics — Inference performance metrics

Configuring TrustyAI

Admin steps:

  • Set managementState: Managed for the trustyai component in the DataScienceCluster CR
  • Configure monitoring for the model serving platform (KServe)
  • Optionally configure TrustyAI to use a MariaDB database instead of PVC storage

Install in a project:

  • Open Data Science Project → TrustyAI → Install Service
  • This deploys TrustyAI components in the project namespace

Monitoring Model Bias

Bias monitoring checks for unfair patterns in model predictions based on sensitive attributes. TrustyAI calculates fairness metrics and provides bias reports.

Sensitive attribute types:

  • BinarySensitiveField — e.g., gender, race
  • AgeSensitiveField — age ranges
  • GenderSensitiveField — gender categories

Data Drift Monitoring

Drift detection compares input data distributions over time against the original training data. TrustyAI identifies shifts that could impact model accuracy.

Drift metrics are calculated on a configurable schedule (default: 5 seconds) and stored in the TrustyAI service.

OpenTelemetry / KServe Metrics

KServe exports metrics via OpenTelemetry:

  • Request metrics — latency, throughput, error rates
  • Predictor metrics — inference counts, batch sizes
  • Auto-scaler metrics — pod scaling events

Metrics endpoint: http://<model-endpoint>/metrics

Grafana Dashboards

OpenShift AI provides pre-built Grafana dashboards:

  • Navigate to OpenShift Console → Observe → Dashboards
  • Select "OpenShift AI" dashboards for model serving metrics
  • Monitor GPU utilization, CPU, memory per model

Hardware Consumption Monitoring

Track GPU and hardware usage via OpenShift monitoring:

  • NVIDIA DCGM exporter for GPU metrics
  • GPU utilization, memory, temperature
  • Model-specific hardware allocation
  • Cost optimization: identify underutilized accelerators
