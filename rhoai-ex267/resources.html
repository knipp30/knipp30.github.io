Resource Allocation

Use nodeSelectors, tolerations, and accelerators to allocate resources

Node Selectors

Node selectors restrict workbenches and model servers to specific nodes based on labels set by the Node Feature Discovery (NFD) operator.

# Example: Schedule workbench only on GPU nodes
apiVersion: workbenches.opendatahub.io/v1
kind: Notebook
metadata:
  name: my-notebook
  namespace: <project>
spec:
  template:
    spec:
      nodeSelector:
        nvidia.com/gpu: "true"

Tolerations

Tolerations allow workbenches to be scheduled on nodes with taints (e.g., GPU taints).

# Add toleration to GPU nodes
tolerations:
  - key: "nvidia.com/gpu"
    operator: "Exists"
    effect: "NoSchedule"

Accelerators

Accelerators (NVIDIA GPUs, AMD GPUs, Intel Gaudi) are configured at the cluster level by the admin, then selectable at the project level.

Admin setup:

  • Install the relevant accelerator operator (e.g., NVIDIA GPU Operator)
  • Install Node Feature Discovery (NFD) operator
  • Navigate to Settings → Hardware profiles (or Accelerator profiles)
  • Create a hardware/accelerator profile: name, resource (e.g., nvidia.com/gpu), labels
  • Set display name, description

Supported accelerators:

  • NVIDIA GPUs (via NVIDIA GPU Operator)
  • AMD GPUs (via AMD GPU Operator)
  • Intel Gaudi AI accelerators (via Intel Gaudi Base Operator)
  • IBM Spyre accelerators (via IBM Spyre Operator)

Data scientist usage:

  • When creating a workbench or model server, select the accelerator and quantity
  • Accelerators appear as resources in the pod spec
  • Example: nvidia.com/gpu: 1 allocates one GPU to the pod

Allocating Model Servers to Nodes

For model servers (InferenceServices), configure node selectors and tolerations in the deployment template:

apiVersion: serving.kserve.io/v1alpha1
kind: InferenceService
metadata:
  name: my-model
spec:
  predictor:
    nodeSelector:
      nvidia.com/gpu: "true"
    tolerations:
      - key: nvidia.com/gpu
        operator: Exists
        effect: NoSchedule
    runtime:
      ...

Persistent Volume Claims

Each Data Science Project gets a default PVC for storage. Admins can configure:

  • Default PVC size (100Gi by default)
  • Storage class
  • Additional PVCs can be added to projects

Storage is accessible in workbenches at: /opt/app-root/src/
