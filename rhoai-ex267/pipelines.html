Data Science Pipelines

Create pipelines with Elyra and KubeFlow SDK, manage artifacts and experiments

Pipeline Overview

RHOAI uses Elyra (a JupyterLab extension) and Kubeflow Pipelines 2.0 SDK for creating and managing data science pipelines. Pipelines can be defined visually in the Elyra Pipeline Editor or programmatically in Python.

Enabling Pipeline Servers

Through the UI:

  • Open Data Science Project → Pipeline tab
  • Click "Enable Pipeline Server"
  • RHOAI deploys the Kubeflow Pipelines backend
  • Wait for the pipeline server to become ready

Creating Pipelines with Elyra

Using the Elyra Pipeline Editor:

  • Open JupyterLab → Elyra → Pipeline Editor
  • Drag and drop components onto the canvas
  • Connect components with arrows (data flow)
  • Configure each component's parameters
  • Save and upload to the pipeline server

Common pipeline components:

  • Data Prep — Load and preprocess data
  • Train Model — Run training with specified hyperparameters
  • Evaluate Model — Calculate metrics (accuracy, F1, etc.)
  • Register Model — Push model to Model Registry
  • Deploy Model — Deploy to model serving

Kubeflow SDK Pipelines

Pipelines are defined using the latest Kubeflow Pipelines 2.0 SDK in Python, then compiled to an IR YAML file.

# Python pipeline using Kubeflow SDK
from kfp import dsl
from kfp.dsl import component

@dsl.pipeline(name='training-pipeline')
def training_pipeline(data_path: str, model_name: str):
    data_prep = component(
        name='Data Preparation',
        container_image='quay.io/myorg/data-prep:latest',
        command=['python', '/app/prep.py']
    )

    train = component(
        name='Model Training',
        container_image='quay.io/myorg/train:latest',
        command=['python', '/app/train.py']
    )

    eval_op = component(
        name='Model Evaluation',
        container_image='quay.io/myorg/eval:latest',
        command=['python', '/app/eval.py']
    )

    train.after(data_prep)
    eval_op.after(train)

# Compile the pipeline
from kfp import compiler
compiler.Compiler().compile(training_pipeline, 'pipeline.yaml')

Container Components

Pipeline steps run as container images. Each component is a Docker/OCI container:

# Example container component
FROM python:3.12-slim
RUN pip install pandas scikit-learn boto3
COPY train.py /app/train.py
CMD ["python", "/app/train.py"]

Managing Artifacts

Pipeline artifacts (models, datasets, metrics) are stored between pipeline steps:

  • Artifacts are stored in the pipeline server's PVC
  • Access via the <component_name>.output property
  • Artifacts are automatically versioned

Kubernetes Pipeline Configuration

Pipelines can configure Kubernetes resources:

  • Node selectors for GPU workloads
  • Resource requests/limits
  • Service accounts for access control
  • Environment variables and secrets

Experiments

Experiments organize pipeline runs into logical groups for comparison:

  • Create an experiment in the Pipeline Server UI
  • Run multiple pipeline variations with different hyperparameters
  • Compare metrics across runs in the Runs view
  • Identify the best performing model version

Pipeline artifacts (models, datasets, metrics) are stored between pipeline steps and can be stored in S3-compatible object storage to avoid consuming local PVC storage.
